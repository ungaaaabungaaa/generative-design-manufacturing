# Contributing

Start with a small reproducible problem and explain the expected result. Keep units, model assumptions, and geometry constraints explicit. Do not add a positive-result requirement that could hide failed or unchanged search outcomes.

Run the Python tests, JavaScript checks, reproduction script, and static build from the README. Mechanics changes need a closed-form or independently derived check. Export changes need bounds, closure, and area/volume checks. Search changes need seeded reproducibility and a fair baseline comparison. Explain every canonical report difference.

For UI changes, check seed selection, generation0/final, baseline overlay, final-export links, keyboard use, and narrow layouts. Keep model constraints and physical limitations visible. Do not label a candidate safe, certified, fabricated, or globally optimal without the required evidence.

AI tools can assist development; contributors remain responsible for understanding and verifying changes. Do not describe assisted code as solely handwritten or an evolutionary search as a trained neural model.

New code uses MIT. Preserve earlier repository history and archived third-party notices. Never force-push shared branches or fabricate contribution dates.
